Android CLI / Capability 02

环境管理：把安装过程写进可复用脚本

适用于新开发机准备、SDK 盘点，以及云端 runner 的构建组件安装。

能力命令入口输出 / 用途
环境识别android info查看 CLI 使用的环境信息；用 --sdk 明确指定 SDK 路径。
组件盘点android sdk list --all检查已安装及可用组件，辅助排查缺包与版本差异。
组件安装android sdk install …安装 Platform、Build Tools、NDK、CMake 等需要的包。
组件维护android sdk update / remove升级或移除指定包；这些命令会改变本机环境。

CarLauncher CI 的实际配置 · Bash

android --sdk="$ANDROID_HOME" sdk install \
  platforms/android-36.1 build-tools/36.0.0 \
  ndk/28.2.13676358 cmake/3.22.1 platform-tools

这是项目已使用的版本组合，不表示所有新项目都应选择相同版本。

Windows 路径写法 · CMD / PowerShell

android --sdk="D:\Android\SDK" sdk list --all

CMD 使用双引号包围路径。之前出现的单引号路径异常属于终端参数解析问题。

工程价值：环境准备可以纳入版本管理、代码审查和 CI 日志；安装后仍应检查关键文件及构建结果，不能仅凭“命令已执行”判定环境可用。

Android CLI / Capability 03

项目与部署：从模板到目标设备

适合创建项目、发现工程产物路径，以及向指定设备交付已有 APK。

命令作用使用边界
create从模板生成项目，可指定名称、目录和 minSdk。本机模板列表参数是 --list；创建会写入文件。
describe生成项目结构、构建目标与输出位置相关元数据。帮助自动化定位产物；不应作为构建成功的证据。
install安装一个或多个 APK，不启动组件。需要已连接且可访问的设备；帮助列出增量安装选项。
run部署 APK 并启动目标组件，可指定设备及调试模式。示例显式传入 APK；构建步骤由 Gradle 先完成。

了解项目 · 示例

android create --list
android describe --project_dir=.

构建后部署 · Linux / Bash 示例

bash gradlew :app:assembleDebug
android run --apks=app/build/outputs/apk/debug/app-debug.apk --device=emulator-5554
设备序列号须按实际环境替换。run --debug 提供调试启动入口，仍需 IDE 或其他调试器连接；本报告没有把部署能力当作完整测试或发布能力。
依据：2026-09-23 本机 android help 与官方文档；示例命令不等于已实跑。04 / 11
Android CLI / Capability 04

设备与 UI：让自动化能够观察应用状态

AVD 生命周期、JSON 布局树和屏幕图像，为界面操作与结果判断提供输入。

虚拟设备管理

emulator create / list / start / stop / remove

可用于准备和回收测试设备。实际使用受系统镜像、宿主机能力与平台支持限制。

官方当前已知问题：Windows 的 android emulator 命令暂不可用。Linux CI 的 SDK 安装成功不能证明模拟器测试也已接通。

UI 观察与坐标定位

layout 输出布局 JSON；screen capture 输出 PNG；screen resolve 将图像标注映射为坐标。

观察结果可供脚本或 Agent 判断；点击、滑动、文本输入仍需配合设备输入工具，例如 adb shell input。

布局与截图 · 示例

android layout --pretty --output=hierarchy.json
android screen capture --output=screen.png

建议保存的证据

  • 设备序列号、系统版本与 APK 来源。
  • 操作前后的布局、截图及执行命令。
  • 可观察结果、失败原因与未执行步骤。
当前版本细节：本机帮助将 layout --diff 标为废弃且无效果。报告采用完整快照示例，不依赖增量布局差异。

Android CLI / Capability 05

知识与 Skills：给 Agent 提供可查证的开发上下文

docs 用于查询知识；skills 用于管理工作指引。两者都需要 Agent 或开发者把结果落实到工程中。

docs：查找并读取文档

搜索 Android Knowledge Base，再读取命中的 kb:// 文档；适合 API 用法、迁移路径和开发实践查询。

android docs search "WorkManager retry"
# 使用搜索结果返回的实际 kb:// 地址
android docs fetch <kb-url>

<kb-url> 是占位符，执行前替换。网络检索结果也要与目标 SDK 和依赖版本对照。

skills：组织可复用工作指引

支持查找、列出、安装、移除和更新 Android Skills。init 为 Agent 安装 Android CLI 指引。

android skills find "testing"
android skills list
# 需要安装指引时再执行
android skills add <skill-id>

Skill 是 Agent 可使用的说明与资源，安装完成不代表功能代码或测试自动完成。

落地示例：为 CarLauncher 增加 Room 前，先查询官方用法与迁移要求，再选择相关指引；结合项目现状实现并验证，最终保存代码、命令与结果。

资料：Android Knowledge Base · Android Skills 官方介绍

Android CLI / Capability 06

Android Studio 联动：把 IDE 的语义能力开放给命令行

这些命令依赖可连接的 Android Studio。它们与普通文件文本搜索或纯 shell 构建有不同的环境前提。

命令族可用于什么
studio check识别运行中的 IDE 实例及打开的项目，作为连接检查入口。
studio find-declaration / find-usages定位符号定义与引用，辅助追踪调用关系和修改影响。
studio analyze-file使用 IDE 文件分析能力发现诊断信息。
studio open-file在 IDE 中打开指定源码文件，连接自动化与人工检查。
studio render-compose-preview渲染 Compose 预览，辅助 UI 检查；不是设备运行验证。
studio version-lookup查询依赖或工具版本信息，升级决策仍需验证兼容性。

最小入口 · 示例

android studio check
android studio find-usages --help
android studio render-compose-preview --help
官方预览能力前提

文档要求 Android Studio Quail 2 Canary 1 或更高版本，项目已打开，并启用及登录 Gemini in Android Studio。本项目本轮没有执行这些联动命令。

Journeys：把用户操作路径交给 Agent 逐步验证

通过自然语言步骤定义操作与预期，Agent 使用设备观察能力执行并判断；CLI 提供底层入口。

  1. 01 · 明确目标

    描述用户路径

    操作步骤、预期状态
    失败与停止条件

  2. 02 · 准备应用

    构建并部署

    记录 APK 与设备
    建立初始状态

  3. 03 · 观察执行

    布局 + 截图

    逐步操作
    依据实际画面判断

  4. 04 · 验证预期

    检查断言

    不以命令成功
    代替功能成功

  5. 05 · 记录结果

    证据与结论

    命令、截图、失败原因
    未执行项单独列出

CarLauncher 可尝试的路径

  1. 打开既有数据库页面。
  2. 添加一条测试记录。
  3. 检查列表出现对应内容。
  4. 返回并重新进入，检查记录仍可读取。

以上仅为候选场景。当前报告未执行，也不据此认定数据库持久化已验证。

与现有测试配合

  • JUnit：快速验证确定的逻辑与数据处理。
  • 设备测试：验证 Android 运行环境中的行为。
  • Journeys：补充面向用户路径的交互与视觉判断。
  • 若 Agent 无法执行某一步，保留失败或未执行状态。
当前本机帮助未提供独立的 android journey 子命令。官方描述的是 Agent 配合 Android CLI 的测试方式，需要设备和 Agent 执行环境。
