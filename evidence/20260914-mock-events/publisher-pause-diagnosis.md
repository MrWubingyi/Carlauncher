# Android 订阅后发布暂停的现场检查

现场：`socket-tap-sd-shared-01`，发布器 PID 50595，单一 mock，Android 与可见 LVGL 同源。
未重启现场进程。发布线程采样位于 `hrtimer_nanosleep`，tee 位于 `pipe_read`，
没有观察到 stdout 写阻塞。Android 与 LVGL 当时持续收到 seq 3743–3754 附近的数据。

解析 service.log：3055 帧，相邻发布帧中位间隔 100 ms，全部大于 300 ms 的间隔为：

| 上一帧 | 下一帧 | 间隔 |
|---|---|---|
| 699 | 1000 | 30335 ms |
| 1899 | 2200 | 30256 ms |
| 3099 | 3400 | 30227 ms |

LVGL 订阅回调 `client=5577` 出现在 seq=112 后，远端订阅回调 `client=0`
出现在 seq=699 后。因此 Android 订阅时恰好进入原有故障注入静默窗口。
这些记录解释了观察到的暂停；不宣称排除了所有其他时刻的阻塞可能。

修改：服务默认连续发布；`--fault-cycle` 显式启用原来的非法值/30 秒静默周期。
进入和退出静默输出 `MOCK_PHASE`。已更新远端二进制和 README。
CTest 2/2 通过，包括故障时间线及默认模式连续跨过两个原静默窗口的 2401 帧测试。
原运行进程仍是旧版本，在原 mock 终端正常停止并重新执行 README 第 2 步后生效。
